# XBrainLab Assistant 人工出題委託說明與模板

版本：`2026-09-19` · 可將本文件單獨交給出題者；不含封存試題。

## 1. 委託目的與交付範圍

我們研究 EEG 桌面軟體 XBrainLab 的英文 Assistant：使用者提出要求後，它是否選對操作、
填對參數，以及在資訊不足或不應操作時正常回覆、不擅自操作。
本次不是 EEG 分類準確率測驗，不考一般 EEG 知識回答品質，也不要求出題者寫程式。

請用中文記錄情境與答案，**使用者對 Assistant 說的句子請用自然英文**。
每題只有一回合、一個主要決策。不要先詢問被測 Assistant 再依它的答案出題。

本文件是出題工作說明，不取代研究規格。三類題庫總目標是 495 題；本次先委託人工完成：

- 165 個原始題目／情境（seed families）。
- 其中 Test 的 66 個原始題各另寫一個人工改寫，共 132 題 Test。
- 合計先交付 **231 個人工版本**：Dev 原始題 66、Validation 原始題 33、Test 132。
- Dev／Validation 其餘 264 個改寫版本暫不包含在本次預設工作量。原規格曾規劃 AI 改寫，
  目前改由人工主導準備，後續採人工或 AI 輔助須由委託人確認，不能暗中改變來源。

全部數量是設計目標，不表示題庫已可執行。請先交少量 **Development 草稿**確認格式與情境；
技術端會補產品狀態與實驗 fixture，不要求出題者猜測內部條件。
Test 草稿及答案也須封存，不能為了格式核對先傳給開發端。

## 2. 三類題目的區別

| 類別 | 如何出題 | 正確行為 |
| --- | --- | --- |
| A：Action | 當前允許操作，意圖與必要參數明確 | 選對操作／視窗及參數，遵守原本的確認流程 |
| C：缺資訊（Clarification） | 操作意圖明確且當前可用，但缺必要值或目的地 | 正常非操作回覆，不猜值執行；本輪不評追問文案品質 |
| N：No-call | 問知識、明確禁止／未授權操作，或要求當前不支援／不可用的操作 | 正常非操作回覆，不開啟不應出現的操作視窗、不改資料 |

沒有回覆、崩潰、逾時，不算正確不操作。模型提出錯誤操作但被系統擋住，也不算模型選對。
出題者寫預期行為即可；實際模型、系統保護與操作完成結果由研究端分層評分。

### 開窗與直接操作務必分清楚

- 匯入、channel、montage、epoch、split、選模型、training settings 是 GUI 交接：
  Assistant 選對並開啟介面，接下來由人填表。不必在一句話內提供表單全部內容。
- 因此「開啟 epoch 設定」沒給時間範圍，**不是**缺資訊題；不能要求 Assistant 自動完成整份表單。
- 濾波、重採樣、參考與正規化是帶參數的操作，必要值不能由 Assistant 猜測。
- 開始／停止 training、重置 preprocessing、清除 training history、compute saliency
  也不是單純開窗；保留軟體原本的確認與執行流程。
- 選對工具不等於 backend 已運算完成；真人填表也不是模型能力。請勿把這些混寫成同一分數。

## 3. 分組與工作量

Family 指一個原始情境、意圖與答案，加上它的語句改寫；不是只看句子有沒有完全相同。
**先分配 family 到 split，再做改寫。** 同一原始題的換句話說或單純換數字，不可跨 split。
不同 split 可以測同一工具，但要獨立設計情境與表達，不從另一組題目改寫而來。

| 題組 | 組數 | 每組 Dev 原始題 | 每組 Validation 原始題 | 每組 Test 原始題 | 原始題合計 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A01–A18 | 18 | 2 | 1 | 2 | 90 |
| C01–C06 | 6 | 2 | 1 | 2 | 30 |
| N01–N03 | 3 | 6 | 3 | 6 | 45 |
| 總計 | 27 | 66 | 33 | 66 | 165 |

每個 Test 原始題再加一個人工改寫，Test 共 132 題。未來 Dev 每 family 共 4 個版本、
Validation 每 family 共 3 個版本時，全題庫才達 264／99／132＝495 題。
改寫是不同語句，不是不同標準答案；增加或拿掉必要資訊，應另列原始情境而非等價改寫。

### A：18 個操作題組

| 編號 | 操作 | 出題時要知道的邊界 |
| --- | --- | --- |
| A01 | 匯入 EEG | 開啟匯入介面；不要求模型自行挑檔案或標籤 |
| A02 | 選擇 channels | 開啟選擇介面；資料／狀態須允許 |
| A03 | 設定 montage | 開啟 montage 介面；不自動填表 |
| A04 | 建立 epochs | 開啟 epoch 介面；合法資料、標籤等由技術端確認 |
| A05 | 設定 data split | 開啟 split 設定介面 |
| A06 | 選擇 EEG 模型 | 開啟模型選擇介面；不是更換 Assistant 語言模型 |
| A07 | 設定 training | 開啟 training 設定介面 |
| A08 | Bandpass filter | 提供下界、上界及 Hz；資料採樣率須能支援 |
| A09 | Notch filter | 提供一個明確頻率及 Hz |
| A10 | Resample | 提供明確的整數目標採樣率及 Hz |
| A11 | Set reference | 提供明確參考方法；指定 channel 時必須確實存在 |
| A12 | Normalize | 明確指定 z-score 或 min-max |
| A13 | Start training | 情境須已完成必要設定；不能假設 start 會代填全部設定 |
| A14 | Stop training | 情境須真的有執行中的 training |
| A15 | Reset preprocessing | 情境須有可重置內容；不要混同刪除來源檔案 |
| A16 | Clear training history | 情境須有可清除的紀錄；不要混同清空整台電腦結果 |
| A17 | Compute saliency | 須有可計算的既有 run／選擇；不是只切換到 Saliency 畫面 |
| A18 | Switch panel | 指定目標 panel；切換與執行該 panel 的操作是不同意圖 |

Panel 目的地為 Dataset、Preprocess、Training、Visualization、Evaluation。
Visualization 可另指明 saliency map、spectrogram、topographic map 或 3D plot；
有指定子視圖時要記錄預期值與必要結果狀態。沒有指定可省略的子視圖，不自動算缺資訊。
這是出題能力範圍，不代表所有畫面在任何資料狀態都可用。

### C：6 個缺資訊題組

| 編號 | 題組 | 可缺少的必要資訊 |
| --- | --- | --- |
| C01 | Bandpass | 下界或上界；不要一併加入無關不可用狀態 |
| C02 | Notch | 要處理的頻率 |
| C03 | Resample | 目標採樣率 |
| C04 | Set reference | 參考方法／參考對象 |
| C05 | Normalize | z-score 或 min-max 方法 |
| C06 | Switch panel | 目標 panel；不是缺少選填的子視圖 |

不要把能合理推導出明確值的說法誤判為缺資訊。答案有爭議時標「待確認」，
在實驗前釐清；不可看了模型回答才補一套有利的解釋。

### N：3 個不操作題組

| 編號 | 題組 | 出題提醒 |
| --- | --- | --- |
| N01 | 資訊／解釋詢問 | 詢問某功能用途，沒有要求套用；不評知識答案內容 |
| N02 | 明確否定／未授權操作 | 說清楚當下不要執行；避免其實是禮貌命令的模糊句 |
| N03 | 不支援或當下不可用 | 技術端須確認真的不可用；不可由作者任意宣布禁止 |

N03 的具體可執行情境需委託人提供經核對的狀態卡。未提供時可先留草稿／待確認，
不得將未核對的假設直接凍結成正確答案。

## 4. 可直接複製的填寫模板

可用 Word、試算表或純文字填寫；一題一筆，不必寫 JSON。請保留以下欄位。

可下載 [CSV 範例（每類一題）](assistant_question_examples.csv)，用 Excel 開啟後依欄位填寫。
檔案採 UTF-8 BOM，三列均為 AI 教學示例，不計入正式人工題數，也不能放入 Test。
正式填寫時另存檔案並移除示例列，依實際作者、來源與 split 填寫；不得直接把 AI 示例改標成人工題。

```text
題號：
Family 編號：
資料分組：DEV / VAL / TEST
題組編號：A01–A18 / C01–C06 / N01–N03
版本：原始題 / 改寫 1 / 改寫 2 / 改寫 3
作者代號、日期：
來源：人工原作 / 人工改寫（其他方式須先經委託人確認）

【目前情境】
目前在哪個階段、已有什麼資料／設定、是否有正在執行的工作？
若使用委託人提供的情境卡，填卡片編號與必要補充即可。

【使用者原話】
一回合自然英文；只有這一格是使用者訊息。

【預期行為】
應開哪個視窗、執行哪個操作，或正常不操作？

【參數／缺少的資訊】
明確給出的值、單位、必要的缺漏；不適用填「無」。

【不應發生的事】
哪些操作、擅自猜值或資料變更不允許？

【疑義／待確認】
沒有就填「無」。若有其他合理答案，先列出，不自行硬選。
```

建議 family 編號如 `DEV-A08-F01`，原始題題號為 `DEV-A08-F01-V0`；改寫保留 family，
只改版本尾碼。這些編號是整理用途，不送給模型。
技術端負責 fixture、工具 schema、可用能力、觀測方式及參數比對，不要求作者填內部 ID。
情境用來建立真實產品狀態，不會把整份答案表貼進模型 prompt。

## 5. 教學示例（非正式題目，禁止放入封存 Test）

以下是 AI 編寫的格式示例，不可冒稱人工原作。正式題目請獨立撰寫，不能只換幾個字就當新 Test。

| 欄位 | Action 示範 | 缺資訊示範 | No-call 示範 |
| --- | --- | --- | --- |
| 題組 | A08 | C03 | N01 |
| 情境 | 已載入 250 Hz EEG，當前允許濾波、無執行中工作 | 已載入可重採樣的 EEG、無執行中工作 | 已載入 EEG，尚未套用 notch |
| 使用者原話 | Apply a bandpass filter from 1 to 40 Hz. | Resample this recording. | What does a notch filter do? |
| 預期行為 | 選 bandpass，使用 1–40 Hz，遵守既有確認流程 | 正常非操作回覆，不自行決定採樣率 | 正常非操作回覆，不套用 notch |
| 參數／缺漏 | 下界 1 Hz、上界 40 Hz | 缺目標採樣率 | 無操作要求 |
| 不應發生 | 改採樣率、套用其他濾波、改動指定頻率 | 猜測一個 rate 並執行 | 開啟操作流程、改資料 |

示例情境仍須技術端建構並驗證；文字宣告不等於系統真的允許操作。

## 6. 出題流程與品質要求

1. 委託人先分派題組、split 與 family 配額，提供可用情境卡及已知限制。
2. 先交少量 Dev 原始題核對模板；缺資訊與 No-call 也要各有示例，不只交正常操作題。
3. 先寫情境與預期行為，再寫自然英文。避免依工具 schema 硬拼句子，也不用故意加罕見英文。
4. 通過格式核對後，依配額完成獨立原始題，再做同一 family 內的改寫。
5. 改寫可改語序、口吻與表達，但保持原始意圖、參數、缺漏與答案；不可加入暗示答案的說明。
6. 人工檢查答案是否唯一或有預先允許的集合，核對否定詞、數字、單位與狀態。
7. 實驗前完成審查並凍結版本；不要根據模型成功／失敗挑題、刪題或改答案。

不要包含真實病人資訊、帳密、私人路徑或他人的未授權資料；使用匿名／示例情境。
不要使用被測 Assistant、生成式 AI 或翻譯模型代寫本次人工題；若確曾使用，必須標記並告知，
不能繼續標為全人工 Test。可以查閱委託人提供的產品說明，不需要自行搜尋既有 benchmark 改題。

## 7. 交付、隔離與封存

建議交付三個互相分離的檔案或資料夾，格式不限：

| 交付物 | 本次內容 | 收件與用途 |
| --- | --- | --- |
| Development | 66 個原始題及答案 | 委託人與開發端；可供工程準備／改善 |
| Validation | 33 個原始題及答案 | 委託人管理；僅供規定的格式準備與後续選版，不用來調 prompt／修產品 |
| Sealed Test | 66 個原始題＋66 個人工改寫及答案 | **只交委託人或指定保管者**；系統凍結前不交開發 agent |

Test 不上傳開發 repo、不貼本開發對話、不放開發 agent 可讀的共享資料夾，也不要把含題文的
截圖、答案、log 或預跑結果轉交開發端。由保管者回報數量、檔案版本／hash 與審查完成狀態即可；
如何隔離／封存由委託人安排，不要求出題者執行陌生腳本。

接觸 Test 的作者／審查者，不得把題文或測試結果用於開發、prompt／RAG 調整。
如有人兼任開發或全部 splits 的出題／評分，須如實記錄角色與接觸範圍；
不能因此宣稱完全獨立盲測或跨評分者一致性。發現外洩時先回報，保留原紀錄並討論處理，
不把已曝光題目重新命名就算未見題。
任何 split 的題目／答案都不作為本實驗 RAG 的答案庫。

## 8. 委託人須補的資訊與方法限制

轉交時請補：聯絡人、各作者負責題組／split、情境卡、交付位置與協議日期。
本文件不自行承諾報酬、期限或授權第三方存取程式／資料。
沒有情境卡的題目可以先寫草稿，但不能當作通過技術核對的正式可執行題庫。

本次產物是有標準答案的人工題庫，不是模型表現或產品可靠性證據；
單人／同團隊作者偏差、角色重疊、情境限制與未驗證事項仍須在研究中揭露。
新增出題者不自動等於新增獨立評分者，也不代表已完成盲審。

研究端權威文件：[研究規格](thesis_protocol.md) 第 3、4 節；
[里程碑](../planning/now.md) M1。離線轉交本文件時不必附上整個 repo；
本版未定案項目仍須由委託人確認，不由出題者自行改動研究設計。
